# Backlog Structure

## Hierarchy

**Product → Epic → Feature → User Story → Task**

Technical Stories, Bugs, and Spikes attach to the nearest meaningful Feature or Epic. GitHub Projects and GitHub Issues are the operational source of truth.

## Work item types

- **Epic:** broad outcome spanning releases or multiple Features.
- **Feature:** cohesive capability delivering recognizable value.
- **User Story:** user-centered, independently verifiable behavior.
- **Technical Story:** technical outcome required for product quality or enablement.
- **Task:** concrete implementation or validation step.
- **Bug:** observed deviation from expected behavior.
- **Spike:** timeboxed research that reduces uncertainty and produces a decision or evidence.

## Backlog policies

Items use stable identifiers, link to parents and requirements, and state dependencies. Product Backlog ordering reflects value, risk, learning, and dependency constraints. Sprint Backlog changes must preserve the Sprint Goal. The complete backlog is intentionally not copied into this document.
